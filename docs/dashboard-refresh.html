Steady dashboard refresh

Implemented and verified: new report data no longer rebuilds the session dashboard.

Recorded 2026-11-19T08:40:13+00:00

Why the dashboard could flash

A report update removed and recreated the dashboard. A timestamp-only dashboard update also replaced every row. A chart nested inside a comparison layout could trigger an unnecessary report rebuild.

What stays steady

Report updates keep the dashboard connected. Dashboard updates change fields within stable rows, and chart detection recognizes nested charts. Open history and focused controls survive updates.

Limit: a changed row can naturally grow or shrink. Saved status still describes recorded work; it does not establish whether an agent process is alive.

Next action: use the updated source. The fixed v0 release predates this dashboard feature.

Verification and design choices

77 unit tests and 42 native UI tests passed, including repeated refreshes with nested charts, changed statuses, open history, keyboard focus and scroll. Desktop and 375 px browser checks passed.

Disabling refresh would hide new results. Keeping the dashboard mounted preserves updates and interaction without changing the server API or stored records.

Only dashboard content is updated in place. Other report sections retain their existing refresh behavior.
